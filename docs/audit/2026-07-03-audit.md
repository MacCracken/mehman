# mehman — Security Audit (2026-07-03, v1.0)

Scope: the mehman swallow-stage surface — the trust boundary where a **foreign,
untrusted binary** runs and its surface/events cross into the sovereign compositor
(aethersafha). Reviewed: `src/{types,surface,shim,sandbox,guest}.cyr` and the
kavach 3.7.0 execution primitives mehman drives. Method: manual review against the
project's hard constraints (no `sys_system` with unsanitized input; validate all
external data; keep the sandbox boundary intact).

## Trust model

A guest is **foreign and untrusted**. mehman's job is to (1) run it inside a kavach
sandbox with a **bounded capability set**, (2) capture its surface, and (3) relay
compositor events to it — without ever letting it reach the AGNOS-native path.
mehman itself is trusted; the guest is not.

## Findings

| # | Area | Severity | Status |
|---|---|---|---|
| 1 | Command injection via the guest command | — | **Mitigated** |
| 2 | Capability boundary (native-path escape) | — | **Enforced** |
| 3 | Surface buffer overflow on capture | — | **Bounded** |
| 4 | Persistent-stream content is not gate-scanned | Low | **Accepted + documented** |
| 5 | SIGPIPE on a self-exited guest mid-stream | Low | **Documented limitation** |
| 6 | Zombie / fd leak on guest teardown | — | **Clean** |

### 1. Command injection — Mitigated
Both execution paths run the guest command through kavach's pre-exec checks before
`fork`: `is_safe_argument` (rejects NUL/CR/newline/ESC control chars that could
smuggle argv tokens) and `check_command` (the runtime guard rejects
policy-violating commands). The one-shot path (`mehman_sandbox_capture_guest` →
kavach `process_exec`) and the persistent path (`guest_start` → kavach
`persistent_spawn`) both apply these. No `sys_system`; argv is built explicitly and
`execve`'d — no shell interpolation. mehman additionally rejects an empty command
(`guest_spec_is_valid`).

### 2. Capability boundary — Enforced
`caps_is_swallow_valid` requires `native_protocol == 0` (the guest may **not** speak
the AGNOS-native compositor protocol) and `mediated_io == 1`. `guest_spec_is_valid`
gates every guest on this before launch, and `guest_spawn` stamps
`caps_swallow_default`. A guest cannot request native access through the public API.

### 3. Surface buffer overflow — Bounded
`surface_blit_bytes` clamps the copy to `surface_size_bytes` (`stride * height`) and
zero-fills the remainder — a guest producing more output than the buffer holds is
truncated, not an overflow. `surface_is_valid` rejects a stride below `width * bpp`,
zero/oversized dims (the `MEHMAN_SURFACE_MAX_DIM` cap guards `w*bpp*h` i64 overflow),
and a null buffer. `guest_spec_is_valid` short-circuits `strlen` behind a non-null
check.

### 4. Persistent-stream content not gate-scanned — Low, accepted
kavach's externalization gate (secret/threat scanning) runs on a **full captured
buffer** — meaningless for an open-ended stream, so `persistent_spawn` output is
**raw** (documented in kavach `src/persistent.cyr` + mehman ADR 0005). The one-shot
capture path (`mehman_sandbox_capture_guest`) **is** gate-scanned. Persistent guests
are therefore for trusted-shape guests behind the capability contract; the pre-exec
command-safety checks still apply. **Recommendation**: a future incremental
streaming scanner (scan-on-read) for untrusted persistent guests.

### 5. SIGPIPE on a self-exited guest — Low, documented
Writing to a persistent guest that already exited on its own raises SIGPIPE (no
`SIG_IGN` wrapper in the stdlib yet). `persistent_send`/`guest_send_input` guard on
the `alive` flag (write-after-terminate is safe), but a guest that self-exits
mid-stream can still SIGPIPE a subsequent send. **Recommendation**: ignore SIGPIPE
in `persistent_spawn` once a `sigaction` stdlib wrapper exists; until then, callers
stop delivering after the guest is known dead.

### 6. Zombie / fd leak — Clean
`persistent_terminate` (called by `guest_evict`) closes the guest's stdin (EOF),
`SIGKILL`s it, `waitpid`s to reap (no zombie), and closes stdout; it is idempotent
via the `alive` flag. The one-shot path `waitpid`s in kavach's `exec_capture`. No
fd or pid leak on teardown.

## Conclusion

No high- or medium-severity issues. The two low findings (4, 5) are inherent to
raw interactive streaming, are documented, and have clear future mitigations; they
do not compromise the capability boundary or the sandbox. The v1.0 surface is
**audit-clean** for the swallow-stage trust model.
