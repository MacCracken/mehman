# 0002 — Consume kavach 3.6.0 as a dist bundle; land the M1 sandboxed foreign host

**Status**: Accepted
**Date**: 2026-07-03

## Context

[ADR 0001](0001-defer-m1-until-kavach-is-consumable.md) deferred M1 because kavach
was not consumable as a Cyrius library. That blocker is now cleared: **kavach
3.6.0** ships a committed single-file `dist/kavach.cyr` bundle (a `[lib]`
aggregation header with no `main()`/demo, generated by `cyrius distlib` — which
does exist in cc 6.3.x; it is merely hidden from `cyrius --help`, which earlier
misled a mehman-side probe). kavach is now consumed the same way as
sigil/patra/bhumi.

Two integration facts shape the decision:

1. **Transitive stdlib is the consumer's responsibility.** `dist/kavach.deps`
   records only kavach's *direct* stdlib leaves; the bundle also pulls sigil
   (crypto) and, via the credential proxy, sandhi/tls/async/bayan. A consumer
   that declares a minimal stdlib fails to *link* (undefined `thread_local_*` /
   `sandhi_server_*` / `TLS_BACKEND_LIBSSL`). kavach's README prescribes mirroring
   its `[deps].stdlib`.
2. **kavach's PROCESS backend does not propagate the guest's exit status.**
   `process_exec` → `exec_capture` returns the captured-output byte count;
   `backend_capture_finish` maps that to `ExecResult.exit_code` = 0 (ran + output
   captured) or 1 (exec failed). The child's `WEXITSTATUS` is consumed by the
   `waitpid` inside `exec_capture` and discarded. So `/bin/true` and `/bin/false`
   both report exit_code 0.

## Decision

Consume **kavach 3.6.0** via `[deps.kavach]` (git + `../kavach` path, `tag =
"3.6.0"`, `modules = ["dist/kavach.cyr"]`), expand mehman's `[deps].stdlib` to
kavach's full transitive set, and source-include `lib/kavach.cyr` in
`src/main.cyr`'s chain after `src/types.cyr`.

Implement M1 as `src/sandbox.cyr` → `mehman_sandbox_run_guest(spec, out_exit_code)`:
validate the guest against the swallow-stage capability contract, then drive
kavach's **PROCESS** backend (`kavach_init` → `config_new` →
`config_backend(PROCESS)` → `sandbox_create` → `sandbox_transition(RUNNING)` →
`sandbox_exec` → `sandbox_destroy`), mapping kavach failure signals onto the
`MehmanError` namespace. `out_exit_code` surfaces kavach's coarse exec status,
**documented as not being the guest's `WEXITSTATUS`.** Ship as v0.2.0.

## Consequences

- **Positive** — M1 acceptance is met: a foreign binary runs sandboxed and is
  reaped cleanly (`/bin/true`, `/bin/false`; 28-assert suite green). mehman has a
  real swallow-stage surface, and the foundation's `MehmanError`/caps/guest-spec
  vocabulary is now exercised end-to-end.
- **Negative** — mehman takes on the full weight of a heavy security engine:
  ~13 MB static scan tables, a transitive sigil/sandhi/tls dependency, and a
  large `[deps].stdlib`. Builds emit known-benign warnings (`duplicate fn`
  last-def-wins; a `lib/sandhi.cyr` arg-count warning on an unexercised
  credential path). `out_exit_code` cannot report the guest's true exit code.
- **Neutral** — `lib/kavach.cyr` + refreshed `lib/sigil.cyr` are vendored into
  the tracked `lib/` (mehman commits its dependency snapshot). If true guest-exit
  fidelity is later required, it is a kavach-side change (or a different backend).

## Alternatives considered

- **NOOP backend.** Rejected — it does no fork/exec and no real reap, so it would
  not satisfy M1 acceptance; it is only an availability probe.
- **Curate a minimal stdlib subset** instead of mirroring kavach's. Rejected —
  the transitive needs cascade; a minimal set fails to link, and curating is
  fragile (kavach README says the same).
- **Block M1 until kavach propagates `WEXITSTATUS`.** Rejected — M1's acceptance
  is "runs sandboxed and is reaped cleanly," which the coarse status satisfies;
  the exit-code caveat is documented, not load-bearing for the swallow stage
  (M2+ care about the *surface*, not the exit).
- **Gitignore `lib/`** (as kavach does) to avoid committing the vendored bundle.
  Deferred — a separate repo-policy change, out of scope for M1; mehman keeps its
  scaffolded track-`lib/` model for now.
